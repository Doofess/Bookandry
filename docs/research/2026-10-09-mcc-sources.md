# MCC data for card-transaction categorisation (Israel-first PWA)

Research date: 2026-10-09. "Verified" means I read the source file or page myself. "Unverified" means I could not confirm it.

## Headline finding

Israeli card exports mostly do not carry an MCC. Where they carry anything, it is the issuer's own Hebrew sector label (ענף). That label is closer to a budget category than a raw MCC. So an MCC list is the wrong primary input. A mapping from Hebrew sector strings to your categories is the right one. No open dataset of that mapping was found, so you build it.

## 2. Israeli exports: is there an MCC or sector?

Evidence is the israeli-bank-scrapers source (MIT, pushed 2026-10-05; API https://api.github.com/repos/eshaham/israeli-bank-scrapers). It reads the issuers' own web APIs, which is what the website and export use.

Transaction type: https://raw.githubusercontent.com/eshaham/israeli-bank-scrapers/master/src/transactions.ts. It has `type` ('normal' | 'installments'), `category?: string` and `memo?`. There is no `mcc` field anywhere.

"סוג עסקה" (transaction type): this is not a merchant category. In Max the field is `planName`, with values such as רגילה, תשלומים, חיוב עסקות מיידי, אינטרנט/חו"ל (https://raw.githubusercontent.com/eshaham/israeli-bank-scrapers/master/src/scrapers/max.ts, enum `MaxPlanName`, lines ~55-70). In Cal it is `trnTypeCode` 5/6/8/9 (regular, credit, instalments, standing order). Do not feed it into categorisation.

Other parsers: caspion (https://github.com/brafdlog/caspion, MIT) has no sector logic. Its `categoryCalculationScript.ts` is a three-merchant stub (internet, electricity) (https://raw.githubusercontent.com/brafdlog/caspion/master/packages/main/src/backend/import/categoryCalculationScript.ts). moneyman (https://github.com/daniel-hauser/moneyman, MIT) has no category text in its README. I did not read its code.

Not verified: real Excel export header rows and sample ענף values for any issuer. I found no public sample files. The GitHub projects raziele/creditCardAnalysis (https://github.com/raziele/creditCardAnalysis) and gonielbaz-git/expense-manager (https://github.com/gonielbaz-git/expense-manager, no licence seen) parse the files, but their READMEs do not list the columns. Their source would show them. To get ground truth, export a statement from each issuer yourself.

## 3. Mappings

- MCC to budget category: the nearest I found is KitKeen/MccTaxonomy, a .NET package with groupings such as Supermarkets (5411, 5412, 5499) and FoodAndDining (5811-5814), per the search summary. Licence and full contents not verified. It is a fast check on your own table, not something to depend on. Writing your own table from greggles is quick, since only about 40-60 MCCs matter for consumer budgets.
- Hebrew ענף to budget category: none found. Searches on GitHub-style terms returned only tools that learn per-merchant (expense-manager, "casa" PR https://github.com/i-sh-sh/casa/pull/1) or hard-code a few merchants (caspion).

## 4. Merchant name to category datasets

None found for Israel, open or otherwise. data.gov.il (https://atlas.co/data-portals/data-gov-il/) hosts government datasets, including a companies registry, but I found no merchant-category dataset. Unverified beyond a search; I did not browse the portal's catalogue. The only Israel-specific merchant mapping is the issuer's own sector field plus the user's own history.

## Recommendation

1. Primary signal: the issuer's sector text (Isracard/Amex `sector`, Cal `branchCodeDesc`, Max category name). Ship a small hand-written table from those Hebrew strings to your categories. Collect the real string sets by exporting one statement from each issuer, and Max's list from `getCategories`.
2. Learn per-merchant overrides locally (the user's categorisation of a merchant name is remembered). This also covers bank exports, which have no sector.
3. Bundle greggles/mcc-codes (Unlicense) only if you ever receive an MCC (for example from a future open-banking feed or manual entry). Reduce it to a trimmed code-to-category table of English labels plus your own Hebrew labels. Do not bundle Visa or Mastercard text.
4. Don't pay for ISO 18245 or build around the scheme PDFs.
5. Check before building: whether Israeli Excel exports contain the sector column. The scraper evidence is from the web APIs, not the downloads.
